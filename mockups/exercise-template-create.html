Notas de design — v2

Mudanças aplicadas

1. Hero removido — h1 vira o nome. O bloco hero escuro foi cortado. A tela agora usa o mesmo chrome do mockup de edit (app-bar + page-header): eyebrow "Modelo · Biblioteca", h1 com o nome em tempo real ("Agachamento livre"), e sublabel de uma linha. No estado vazio o h1 vira "Sem nome ainda" em --brand-steel. Coerência create/edit é total.

2. Tipo virou segmented-toggle com ícones. Substituído o select por grid de 5 botões (Força, Cardio, Mobilidade, Alongamento, Core) com ícones lucide e label embaixo. Em viewports estreitos abaixo de 420px, faz wrap em 3+2 — mantém touch target de 44px.

3. Visibilidade pública usa accent + dialog. O switch de "Tornar público" agora ativa em laranja (--brand-accent), sinalizando que é estado fora do padrão. Na primeira ativação abre um confirm dialog explicando o impacto externo, com CTAs "Tornar público" / "Cancelar".

4. Vídeo vira hero do card (revisado). A thumb 64x64 ao lado do input invertia a hierarquia: input dominava 90% da largura e a prévia ficava ilegível. Agora o vídeo ocupa a largura útil do card num stage 16:9 (max-height 360px), com play centralizado, badge "YouTube" no canto e maximize overlay. URL e ações descem para metadata compacta abaixo — input com ícone link, "Escolher da biblioteca" e "Remover vídeo" como btn-link. Estado vazio usa stage tracejado em --brand-mist com hint contextual. Mobile mantém o pattern (já era coluna única).

5. Descanso ganha chips de atalho. Pattern espelhado do modo Tempo (60/90/120/180s). Acelera input recorrente, mas mantém o number input para casos exóticos. Touch target 44px.

6. Footer com hierarquia clara. Cancelar virou btn-link (texto puro, flex 0). Criar mantém btn-primary com flex 1 para cobrir maior parte do footer mobile. Reduz peso visual da ação destrutiva sem escondê-la.

7. Rail lateral removido — desktop em coluna única. O preview "Aluno verá" e o tip de Visibilidade saíram. Form ocupa coluna única centralizada (max-width: 760px, margin: 0 auto) — evita inputs esticados em telas largas. O tip de Visibilidade virou info-banner inline acima do toggle, ficando contextual no momento da decisão.

8. Notas com contador e textarea com maxlength. Header da label virou row com contador 0/240 alinhado a direita. Tipo virou textarea[maxlength=240] — limite duro previne campo absurdo que o aluno teria que rolar no app.

9. Removida copy "Rascunho — clique em criar". Sugeria persistência automática que não existe. O botão primary já resolve a ambiguidade.

10. Switch ARIA explícito. Inputs de toggle agora carregam role="switch" + aria-labelledby + aria-describedby apontando para título e sublabel.
