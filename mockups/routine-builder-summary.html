Especificações

Decisões UX que precisam ser respeitadas

1. Layout · 3-column cockpit

  • Workspace = flex row com 3 colunas: .outline (288px fixo) + .canvas (flex:1) + .volume-rail (240px fixo). IDE-style.
  • Canvas-inner deixa de ter max-width:760px — ocupa toda a largura entre rails (~760px naturais em 1360px viewport).
  • Volume rail some abaixo de 1024px junto com o outline. Em mobile, vira .volume-card no topo do canvas (Balance score + 1 linha de alerta).
  • Em 768–1023px o canvas ocupa toda largura. Volume vira card. Outline vira drawer.

2. Outline rail · header-only por padrão

  • Default expand state mudou (v3): apenas o treino atual fica expandido (lock explícito por click; "in view" via IntersectionObserver é passivo e não troca o expanded). Demais treinos ficam header-only — sem peek-3, sem "+N exerc.". O peek-3 era dead weight 70% do tempo.
  • Math: antes 5 treinos × peek-3 + atual = ~880px (estourava 812px viewport). Agora 1 expandido + 4 headers = ~340px. Resto vai pra "Sem dia" + breathing room.
  • User clica chevron pra expandir treino específico. Click no nome = scroll até o card + auto-expand.
  • Header colapsado mostra: day-tag + letra + nome + count exercícios + ×N dup badge se houver duplicata, e cor warn no meta se incompleto.
  • "Sem dia" pin no topo: quando há treinos sem dia, exibe um chip warn ⚠ N treino(s) sem dia · <nome> logo após os filtros — clicável, scroll até a section "Sem dia".
  • Filter chips · busca: filtram tanto rail quanto canvas. Placeholder atualiza pra "Buscar exercício…" (escopo claro).
  • Pulso colorido tem tooltip on hover na section label com legenda completa (verde = completo, laranja = incompleto, cinza = sem dia).
  • Densidade do exercício no rail: 1 linha de 24px — nome + mini-stat. Carga/descanso só no canvas.

3. Duplicata cross-day · sinal forte (não 14px perdido)

  • Detecção: match por exerciseTemplateId (preferencial) ou nome normalizado (lowercase, sem acento). Roda client-side a cada mutation.
  • Sinal triplo (não único):
    1. Row tintado warn (rgba(181,90,2,.06) background no rail · rgba(.07) + inset-shadow 2px no canvas).
    2. Badge ×N em --warn-c ao lado do nome — comunica frequência ("aparece em N treinos").
    3. Ícone copy 11px como reforço terciário, com tooltip "Já existe em Treino B · Ter".
  • Header colapsado: badge ×1 dup aparece nos meta do training-head — sinaliza que existe duplicata sem precisar expandir.
  • No canvas (exercise-row): além do tint warn, linha de meta inclui · repetido em B · Ter em cor warn weight 600.
  • AddExercise sheet · cross-day mini-list: ao selecionar exercício que já existe, banner expande pra mini-list mostrando até 3 ocorrências (tag dia, nome do treino, séries×reps · carga · descanso) — cada row é tappable e faz jump-scroll. CTAs: Cancelar / Mover de <Treino X> (novo) / Adicionar mesmo assim (primário). "+N mais" se >3.
  • Não é erro — é informação. Cor warn (laranja), nunca error (vermelho). Trainer pode prescrever propositalmente (progressão, A/B testing de protocolos).

4. Volume rail v1 · Balance + heatmap

  • Balance score XL no topo (44px Space Grotesk · StatDisplay) — score 0–100 baseado na cobertura de grupos vs metas. Bar gradient mostra fração ok/alerta. Sub-line dá causa principal.
  • Muscle list: 7 grupos (Peito · Costas · Pernas · Ombro · Tríceps · Bíceps · Core). Cada row = nome + sets count + bar com target marker (linha vertical na meta) + flag warn se <meta ou >meta.
  • Cores: verde (em meta), warn (abaixo OU acima — ambos são problema). Vermelho NUNCA aqui (não é error).
  • Atualiza em tempo real a cada mutation (add/remove/edit exercise). Aggregação client-side por muscleGroup tag do template.
  • Settings icon abre sheet pra configurar metas por grupo (12 sets Peito, 16 Pernas, etc) — defaults baseados em frequency × experience-level do aluno.
  • Mobile: volume-card no topo do canvas mostra apenas Balance score + 1-line alert. Tap expande sheet completa com a heatmap.

5. Reorder · drag handles

  • Desktop: grip-vertical (lucide) à esquerda da exercise-row e do training-head. Visível em opacity:0 default, opacity:1 on row hover. Cor --outline idle, --steel hover.
  • Mobile: long-press (500ms) ativa drag mode em qualquer card. Sem handle visível — toda a row vira draggable após hold.
  • Reorder de treinos no canvas → reordena array da rotina (ordem A/B/C/D/E preserva letras se nome não foi customizado).
  • Reorder de exercícios dentro de um treino → reordena array de prescrições. Index column (1, 2, 3) recalcula automaticamente.
  • Cross-training drag (mover exercício de A pra B) é opcional v1.1 — começar só intra-training pra reduzir complexidade.

6. Polish · médios

  • Save status: "Salvo · há 12s" timestamp relativo. Atualiza a cada 10s. Após 5min vira "Salvo · há alguns min".
  • Top-right CTA: "Salvar e fechar" (não "Concluir" — não há concluir, só sair).
  • More-vertical menus: hover-only no desktop (atribute data-more + opacity transition). Sempre visíveis no mobile (touch UX).
  • IntersectionObserver: separado do "selected". IO marca in view (passivo) → atualiza só o sticky drawer trigger no mobile. Click expande/colapsa explicitamente — nunca via scroll.
  • Mobile rail rows: min-height 36px (variant --mobile) — toques mais generosos no drawer.

7. Edge cases

  • Rotina vazia: outline + volume rail mostram empty state ("Adicione treinos pra ver a estrutura"); CTA principal mora no canvas via FirstTrainingHero.
  • Volume sem dados: antes do 1º exercício, balance hero mostra "—/100" muted; muscle list em estado —.
  • Read-only: esconde drag handles, "+ Adicionar", more-vertical. Volume rail e duplicata signaling permanecem (são informação, não ação).
  • Nome longo (35+ char): truncate ellipsis · tooltip native title.
  • Sem grupo muscular taggeado no exercise: agrega em "Outros" no volume rail. Não conta pra balance score.

8. O que NÃO mudar

  • Topbar, IdentityStrip, BuilderStatsRow — layout preservado (apenas save-status ganha timestamp e CTA renomeado).
  • WeekOverview e TrainingItem expandido — comportamento e classes existentes mantidos.
  • Sheets existentes (AddTraining, ImportTemplate) — sem alteração visual; AddExercise ganha apenas a cross-day mini-list condicional (se não há duplicata, sheet é idêntico ao atual).
  • Tokens (--warn, --success, --steel) — reutilizados, zero novo hex.
  • Rotas e contratos de API — sem mudança. Tudo no client.
