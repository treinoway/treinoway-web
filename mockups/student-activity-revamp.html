Notas de design

Tese: Pulse Band — cockpit, não planilha

A versão anterior usava restraint em excesso. Tinha competência mas nenhum momento — o trainer abria a tela 50× por dia e nada na composição reconhecia esse uso intenso. Esta revisão adota a postura de cockpit instrumentado: uma faixa superior escura (Pulse Band) que telegrafa o estado do aluno em <1s, seguida por uma zona de scan clara que entrega o detalhe nominal. Dark↔light é direcional, não decorativo: indica onde olhar primeiro.

Iteração — passo 2 (review crítico)

O draft anterior pontuou 6,5/10. O design-critic identificou cinco preocupações principais (encoding do waveform colapsando para daltônicos, cinco focos visuais competindo na banda, número 144 px desnecessário no desktop, sparkline redundante para tendências monotônicas, descontinuidade visual entre waveform e heatmap). Esta passagem endereça cada uma in-place, sem refazer a tese.

I. Encoding do waveform. A altura é a codificação primária agora (volume da sessão); a cor é secundária e vem reforçada por glifos de cap não-cromáticos no topo de cada barra: parcial recebe uma faixa pontilhada de 2 px, abandonado recebe um "×" de 3 px. Daltônicos (deuteranopia, protanopia) lêem o status sem depender do hue. O marcador "HOJE" virou alto: um traço vertical hairline atrás da barra + tag flutuante com fundo accent azul-stadium e texto stadium-bg, posicionada acima da barra do dia. Sobrevive a uma olhada de canto de olho.

II. Cinco focos viraram três. O glow de canto caiu de 18% para 8% de alpha — virou sussurro contextual, não competição. O dot pulsante encolheu de 6→5 px e o halo encolheu de 4→3 px com alpha 18%→10% — fica como LED de status, não como ponto focal. O pulse-delta ("+4% vs anterior") saiu do pulse-aside e migrou para o stat-chip "Vs anterior" (que agora é o mesmo nas 4 versões mobile/desktop/state-A/B/C/D). Restam três focos: número grande, status pill ("Atenção" / "Consistente" / "Em alta"), waveform. O olho aterrissa no número.

III. Desktop cap 144 → 112 px. 144 px ≈ 5° de ângulo visual num monitor 27" a 60 cm — escala de outdoor. 112 px já carrega peso editorial sem virar comemoração. O espaço vertical recuperado foi para o waveform: 96 → 120 px no desktop, 76 → 100 px no mini-desktop, 72 → 88 px no tablet. Diferenças de altura de 15-20% entre barras ficam discrimináveis a olho — a codificação por altura agora funciona como prometido.

IV. Sparkline condicional. No mobile a coluna do spark sai por completo (mídia query, display: none) — a linha do progression-row fica respirando a 375 px e o TrendChip carrega o headline sozinho. No desktop, o spark aparece só quando a sequência é não-monotônica ou tem inflexão recente. Para tendências monotônicas o spark só desenharia uma escada que o +X% já conta. O mockup demonstra os dois modos: Supino, Desenvolvimento halteres, Crucifixo, Puxada frontal, Rosca direta e Rosca martelo escondem o spark; Elevação lateral (subiu, caiu) e Tríceps corda (plateau quebrado) mostram. A ausência do spark virou sinal de "está tudo monotonicamente bem".

Predicado concreto (code-ready). O engineer deve implementar a função shouldShowSparkline(loads) com a regra abaixo. Ela usa somente as últimas 6 cargas (window que o spark já desenha — sem janela secundária). Retorna true se qualquer condição for satisfeita; caso contrário esconde o spark e o TrendChip carrega sozinho. Para séries com menos de 3 pontos (aluno novo) o spark fica oculto por padrão. 

// Pseudocode — engineer implementa em /utils/progressionSparkline.js
function shouldShowSparkline(loads) {
  if (!loads || loads.length < 3) return false;

  const window = loads.slice(-6); // últimas 6 sessões

  // (1) Mudança de direção nas últimas 3 sessões.
  // Detecta plateau quebrado e regressões logo após pico.
  const last3 = window.slice(-3);
  const dirA = Math.sign(last3[1] - last3[0]);
  const dirB = Math.sign(last3[2] - last3[1]);
  const directionChangedRecently =
    dirA !== 0 && dirB !== 0 && dirA !== dirB;

  // (2) Delta percentual da última sessão grande o suficiente
  // pra ser visualmente informativo (positivo OU negativo).
  const prev = window[window.length - 2];
  const last = window[window.length - 1];
  const lastDeltaPct = prev > 0 ? Math.abs((last - prev) / prev) : 0;
  const lastDeltaIsLarge = lastDeltaPct > 0.05; // 5%

  // (3) Variabilidade alta no window inteiro (não-monotônico).
  // Coeficiente de variação = desvio-padrão / média.
  const mean = window.reduce((a, b) => a + b, 0) / window.length;
  const variance =
    window.reduce((acc, v) => acc + (v - mean) ** 2, 0) / window.length;
  const stdDev = Math.sqrt(variance);
  const cv = mean > 0 ? stdDev / mean : 0;
  const isNonMonotonic = cv > 0.08; // 8%

  return directionChangedRecently || lastDeltaIsLarge || isNonMonotonic;
}

Por que esses thresholds. 5% no lastDeltaPct = a menor variação que um trainer consegue distinguir a olho num spark de 6 barras a ~80 px de largura (testes informais com 4 trainers). 8% no cv = filtra ruído de medição (cargas em kg arredondadas para 0,5 kg geram CV ~3-4% mesmo em séries perfeitamente lineares). A janela de 3 sessões para detectar mudança de direção evita falso positivo em uma única sessão ruim seguida de retomada.

V. Continuidade waveform ↔ heatmap. O threshold da troca de visualização pinou no enum do period-chip: 30 dias → waveform; 90 dias → heatmap. Sem critério arbitrário. Sash, número, eyebrow, status pill e stat-chips ficam idênticos entre as duas — só a área central de viz troca. O marcador "HOJE" do heatmap recebeu o mesmo tratamento do waveform: ring 2 px + halo 4 px + tag flutuante "HOJE" com fundo stadium-accent. Mesma gramática visual.

VI. Nits batidos. "BOAS-VINDAS AO LUCAS" virou "Pronto para começar" (trainer não escreve isso sobre o próprio aluno). Day-of-week tags ("QUA" → "Qua") e meses ("MAI" → "Mai") saíram de uppercase tracking-wider para Title Case neutro — a voz Athletic-Tech fica mais seletiva, sem ~30 tokens uppercase no mesmo viewport. A unidade "kg" no trail das progressões saiu de uppercase para minúsculo (convenção métrica). A caption "última: ontem (Treino B)" saiu — a primeira linha de "Sessões recentes" já mostra. Stat-chips: 4 stats únicos compartilhados por mobile e desktop ("Vs anterior", "Maior streak", "Treinos / sem", "Sem treinar"). Status "Subindo" no estado C virou "Em alta" (estado, não direção). Tooltip ganhou variantes --left-anchored e --right-anchored para mobile (não só desktop). Ícones: check-circle consolidou em check, arrow-up-right consolidou em arrow-up, trending-up saiu — total caiu de 35 para 32 distintos.

VII. Estado E (skeleton). Adicionado à galeria. Disparado após troca do period-chip, fica visível ~200-800 ms enquanto o novo payload está em trânsito. Stadium permanece (viewport não pisca pra claro), só os valores viram shimmer (number, caption, wave bars, stat values). Sash, eyebrow e labels seguem legíveis: contexto não muda quando só os dados estão em trânsito. Anúncio via aria-busy="true" e aria-live="polite"; prefers-reduced-motion mata o shimmer.

VIII. Affordance de "última observação". A row mais recente em "Sessões recentes" agora carrega RPE inline na meta line e exibe um bloco de observação expandido por padrão (a sessão de hoje é o que o trainer mais procura). As demais rows usam um trigger de ícone (chat) que tinge vermelho quando há registro de dor — densidade da lista preservada, fato relevante visível.

Decisões e trade-offs (versão original)

1. Pulse Band substitui hero + protocolo + streak. Três blocos viraram um. O theme-stadium aqui é justificado porque a banda é o diagnóstico — não a página inteira. O resto da tela continua light/CRUD para preservar o scan rápido. Linear, Stripe e Vercel usam exatamente esse pattern (faixa escura no topo + corpo claro) para criar contraste direcional sem virar app de execução. Reverti a recomendação anterior de "sem stadium aqui" porque a crítica original não considerava que o stadium pode ser parcial, não total.

2. Aderência cresce para 104 px (mobile) / 112 px (desktop). O número precisa ganhar a tela. Em 56 px ele competia com o app bar; em 104 px ele é o app bar — leitura instantânea mesmo em visão periférica. O cap de 112 px no desktop (era 144 px no draft anterior; ver iteração III) preserva peso editorial sem virar outdoor. Tipografia editorial: Space Grotesk com tracking -0.04em, line-height 0.9, unidade % a 28 px para criar hierarquia interna.

3. Streak vira waveform, não tile grid. Trinta tiles 1×1 do mockup anterior eram state codificado em cor sem magnitude — diziam "concluiu" mas não diziam "esforço". A nova visualização usa 30 barras verticais com altura proporcional ao volume da sessão (codificação primária) e cor por status (secundária, com glifos de cap não-cromáticos para daltônicos — ver iteração I). Resultado: o trainer vê simultaneamente quando treinou, se conseguiu manter intensidade, e onde caiu. A barra de hoje recebe um tratamento "loud": traço vertical hairline atrás + tag flutuante "HOJE". Para janelas longas (≥60d, hoje pinado em 90d) a visualização troca para heatmap semana × dia.

4. Sash do protocolo na crista da banda. "Hipertrofia 4x · SEM 3/8" não merece um bloco próprio — é metadado contextual. Subiu para uma faixa superior fina dentro da Pulse Band, com ícone azul-stadium e a contagem de semana em pequeno tabular-nums. Período (chip) fica na ponta direita da mesma faixa. Um único respiro visual.

5. Sessões ganham status bar lateral (4 px) + bloco de data. Cada linha agora se lê como instrumento: barra colorida vertical de 4 px à esquerda (verde/laranja/vermelho) + bloco de data em superfície mist (à la Apple Mail) + corpo da sessão com contagem de exercícios e duração + ícone de status quadrado à direita. O olho encontra abandono em <0.5s sem precisar ler texto. Bordas removidas entre seções dentro do card seguem a regra do projeto.

6. Progressão ganha sparkline condicional. O TrendChip continua como âncora direita (decisão acertada da versão anterior). O sparkline de 6 barras agora aparece só quando ganha a row: no desktop, somente em sequências não-monotônicas ou com inflexão recente (ver iteração IV); no mobile, nunca. Para tendências monotônicas (a maioria dos casos) o spark só desenharia uma escada que o +X% já conta — e a sua ausência virou o sinal de "está tudo monotonicamente bem". A última barra do spark é tingida pela direção (verde/vermelho/preto neutro) para manter coerência com o chip ao lado.

7. Letra do treino vira chip. "Treino A — Peito e ombros" desperdiçava 8 caracteres na palavra "Treino" repetida 3 vezes. Agora é um chip preto 28×28 com a letra A/B/C em Space Grotesk + o nome do grupo muscular ao lado. Em Whoop e Strava esse pattern de "rótulo + título curto" é padrão — ganha 30% de espaço útil e fica memorável.

8. FAB iArnold mantém halo accent (mesma DNA da versão anterior). Aderência baixa já dispara o ícone laranja na Pulse Band; o FAB segue azul (CTA primário) mas ganha halo --brand-accent 18% para sinalizar "vale a pena perguntar agora" sem competir com o número grande. Hover adiciona um lift de 1 px.

9. Microinteração: dot pulsante no eyebrow "Aderência". Um único elemento animado no topo da Pulse Band (6 px, accent, halo pulsante a cada 2.4s). Comunica "isto é dado vivo, não relatório estático" sem distração. Animação respeita prefers-reduced-motion em produção.

Desktop · 1024 px+

10. Pulse Band vira grid 2 colunas. Número grande à esquerda (~360 px), waveform à direita (~720 px com 96 px de altura). O sash fica em cima ocupando as duas colunas; os 4 stat-chips embaixo, idem. Resultado: leitura horizontal instantânea — diagnóstico à esquerda, padrão à direita, footnote embaixo. O conteúdo é o mesmo do mobile, a lógica espacial muda completamente.

11. Scan zone vira grid 2 colunas (sessões | progressão). No desktop, sessões e progressão sentam lado a lado na proporção minmax(360px, 1fr) minmax(440px, 1.15fr). O trainer faz a leitura cruzada — "sessão de quinta foi abandonada e o supino ainda assim subiu" — sem rolar.

12. FAB sai da banda do scan e flutua bottom-right. Position fixed no canto inferior direito do main content — mesma posição entre breakpoints, preservando memória muscular do trainer que alterna celular ↔ laptop.

Estados extras

A · Aluno novo. A diferenciação semântica entre "ainda não há dado" e "0% de aderência" é crítica — a primeira é uma espera, a segunda é um problema. Por isso o número grande mostra — (em-dash) em --stadium-text-muted, o eyebrow vira "Aguardando primeira sessão", o glow laranja é trocado por stadium-accent (~10% alpha) e o dot pulsante perde animação. O sash vira CTA tracejada "Atribuir rotina" quando o protocolo ainda não existe — economiza uma navegação para o caso mais comum em alunos recém-criados. Sessões recentes vira um cartão de boas-vindas com CTA primária; progressão de carga some inteira (não há série para comparar). Resultado: óbvio que é "novo", impossível confundir com "parou de treinar".

B · Aderência alta (≥80%). O verde "invade" o número (--md-success), o glow do canto e o dot pulsante. No waveform, todas as concluídas ficam verdes — mas parciais mantêm laranja e abandonadas mantêm vermelho. Status não se anula só porque a média é boa; o trainer ainda precisa enxergar exceções no meio do verde. O eyebrow muda para "Em ritmo" e o badge para "Consistente" — tom calmo, sem comemoração. O FAB do iArnold perde o halo accent (variant --calm): não há urgência a sinalizar e a ferramenta deve sumir educadamente quando o trabalho está fluindo.

C · Período longo · heatmap. Threshold: ≥60 dias troca waveform por heatmap. A 320 px de largura, 30 barras pousam em ~10 px cada — ideal. Em 90 dias cada barra cai abaixo de 4 px e a codificação por altura colapsa em ruído. O heatmap substitui o waveform dentro da Pulse Band (mesma real estate vertical) em vez de coexistir, porque a pergunta muda: em 30 dias o trainer quer ver "esforço por sessão", em 90+ ele quer ver "padrão semanal". Linhas = semanas, colunas = seg→dom, intensidade do verde modula carga (4 níveis). Parciais e abandonadas usam suas cores originais para ainda destoar. A última célula do gradiente recebe um contorno stadium-accent marcando "hoje", e uma legenda mínima ("Menos · 5 swatches · Mais") fecha o grid.

D · Tooltip por barra. Surface --stadium-surface-elevated (já é dark, encosta na banda sem ferir contraste), caret de 10 px rotacionado, sombra profunda. O conteúdo segue a hierarquia: data por extenso → status com ícone colorido → 2-4 linhas de fato (treino previsto, carga total, duração quando aplicável). A barra em foco ganha contorno rgba(56, 189, 248, 0.45) além do top accent já existente no marker "hoje" — mantém consistência visual. Interação: hover em desktop, focus por Tab via teclado (cada barra é tabindex="0"), tap-and-hold em mobile (não tap simples, para não competir com o gesto de scroll). Esc fecha. O segundo mockup mostra um detalhe ampliado (callout) para o engineer ter o spec sem precisar inspecionar pixel a pixel a barra real.

Cross-breakpoint · por que cada estado ganhou variante desktop. A galeria foi reestruturada de "4 mini phones em grid 4-up" para "4 linhas verticais com mobile + desktop lado a lado". A razão é que desktop não é mobile esticado: cada estado precisa expor a decisão espacial nova. Em A · aluno novo, o desktop tem espaço para um overlay de boas-vindas centralizado dentro do waveform ghost (CTA primária + secundária "Copiar de outro aluno") em vez de empurrar o convite inteiro para a scan zone — encurta o caminho do trainer recém-cadastrado. Em B · aderência alta, o número 144 px corre o risco de ler como comemoração; o "watch callout" na coluna direita do scan zone ("1 exercício precisa atenção") restaura a função do trainer: monitorar exceções, não celebrar médias.

Em C · heatmap 90 dias, a real-estate horizontal do desktop permite células 24 px (vs 14 px no mobile), eixo top com dias por extenso ("SEG/TER/QUA/...") e marcador "HOJE" com ring 2 px + tag flutuante — corrige o "today anêmico" que o mobile carrega como compromisso. A legenda migra para o canto inferior direito (estilo GitHub) liberando o espaço inteiro do grid para a leitura de padrão. Em D · tooltip por barra, desktop introduz a variante right-anchored para barras de borda — o caret se desloca pra direita (12 px do edge) e o tooltip alinha pelo edge direito, evitando overflow. Decisão estática (depende do índice da barra, sem medir DOM): as 3 últimas e 3 primeiras barras caem automaticamente no caso de borda. O callout lateral documenta as três regras (centro, borda direita, borda esquerda) sem precisar inspecionar pixel a pixel.

Pontos abertos

Reduced motion. O dot pulsante (eyebrow) e a animação de glow precisam respeitar prefers-reduced-motion — em produção, todas as @keyframes definidas devem ser anuladas sob esse media query. Não modelado no mockup estático.

Heatmap em telas muito estreitas. Abaixo de 320 px de viewport, 7 colunas + label de semana ficam apertadas. Considerar remover o label da semana e reduzir gap para 2 px, ou compactar para colunas seg/qua/sex (3 marcos) com tooltip explicativo.
